# v8 편집 기준과 구현 확인

## 분량 판단 정정

- 사용자 정정에 따라 펫 원고와 글자 수·쪽수를 맞추려던 v7의 축약 기준을 폐기했다. v7은 최종 권장본이 아니다.
- 통합 목차의 담당 범위, 직접 구현과 공동 확장의 경계, 시스템을 이해하는 데 필요한 설명과 기술적 중요도를 기준으로 재편했다. 목표 쪽수는 설정하지 않았다.
- 전선현 담당은 Enemy·시네마틱 전체, 보스 공통·패턴 운용·Stage3 일부, 카메라 가림, 경계 기믹, 진행 복원·레벨·설정·성능 등 여러 영역에 걸친다. 펫 2장 단독 원고와 분량을 직접 맞추는 것은 적절하지 않다.
- 커밋 수나 변경 줄 수를 기여율로 환산하지 않았다. 최초 구현·후속 확장·공통화와 팀원 고유 구현을 앞의 기여 표에서 구분했다.

## 복원한 내용

- Enemy 데이터 분리 이유, AI 초기화·판단 경계, 루트 모션·비행 조건, 패턴 확장 계약과 수명, 피해 판정의 재진입·대상 계약.
- 보스 페이즈 전환 그림·데이터 검증·재도전, 주·보조·상시 실행 모델, 매니저·Director·표시 책임, 돌진·머니건 내부 동작.
- 시네마틱 요청 옵션, 콜백 재진입과 리스너, BP 연결, 스킵 후 복원 책임, Stage3 전용 처리와 엔딩 복구.
- 방 안·밖 판정 경로, 캐시 분류 기준, 렌더 상태 보존, 볼륨·그룹의 범위, 저장 복원 그림, 시간대·레벨 경로 검증.
- 시스템별 문제 해결과 설정·확장 지점을 복원했다. 공동 절은 확장한 연결 지점만 설명한다.
- 반복되는 기여 표·날짜 이력·촬영 빈 상자는 복원하지 않았다. 담당자는 앞부분에만 표기한다.

## 이번에 추가 대조한 코드

- 편집 중 작업 폴더에서 패턴 분리 변경이 진행됐다. 최종 대조 때 `EnemyPatternComponent.cpp`가 `FEnemyPatternCatalog`·`EnemyPatternOccupancy`를 실제 호출하고, `EnemyPatternComponent_Persistent.cpp`로 상시 처리가 옮겨진 것을 확인했다.
- v8의 5.5에 목록·Spec·선택 설정, 점유 계산·추첨, 실행 슬롯·요청 수명, 상시 구현 파일의 책임을 구분했다. 완료된 책임 분리를 향후 과제로 남기지 않았다.
- 이는 소스 구조 대조이며 이 문서 작업에서 해당 변경을 빌드하거나 플레이 테스트한 결과는 아니다. 게임 코드는 수정하지 않았다.
- 기존 구현 정정의 상세 근거와 현재 에셋에서 확인할 사항은 v6.check.md의 목록을 유지한다.

## 통합 편집

- 구조·흐름 그림은 17개이며 호출 시퀀스 4개를 포함한다. 기본 본문은 12pt로 짧은 설명·목록 중심을 유지했다.
- 실제 게임 캡처는 추가 촬영하지 않았다. 최종 통합 시 패턴 설정·판정 디버그·Stage3·가림 전후·조명 전후 등 설명을 입증하는 화면을 추가할 수 있다.
- 공동 절과 공통 장은 다른 원고와 통합할 때 중복 개요를 제거하고 연결 설명을 병합한다.
- 최종 렌더링은 Word PDF 출력 기준 50쪽이다. 이 수치는 편집 결과이며 목표 분량이나 기여율의 수치 평가가 아니다.
