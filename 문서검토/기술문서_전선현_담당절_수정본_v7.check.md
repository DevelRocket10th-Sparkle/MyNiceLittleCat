# v7 편집 결과와 남은 확인 사항

## 개편 기준

- 본문 12pt, 장 제목 18pt, 절 제목 14pt. 펫 문서의 짧은 설명·목록·구조 그림·시퀀스 표현을 참고했다. 원본 참고 문서의 큰 빈 공간까지 재현하지는 않았다.
- 담당과 공동 기여는 앞의 표에만 모았다. 장·절·클래스·다이어그램의 사람 표기를 제거했다. 기존 단독 구현과 팀원 최초 구현을 혼동하지 않도록 앞 표에서 구분했다.
- v6 약 54,321자에서 v7 약 17,284자로 줄였다. 표와 본문을 같은 방식으로 합산했으며 다이어그램 안의 글자는 제외한 값이다. 펫 문서는 같은 집계로 약 28,674자다.
- v6 Word 64쪽에서 v7 Word 28쪽으로 재편했다. 참고 펫 문서는 Word 통계 51쪽, PDF 출력 50쪽으로 차이가 있어 페이지 수는 렌더링 조건을 함께 보아야 한다. 글자 수와 본문 크기도 함께 비교했다.

## 먼저 줄인 부분

1. 비어 있는 촬영 영역과 긴 코드 캡처 자리
2. 절마다 되풀이되던 개요·기록·기여 표
3. 상세 날짜 이력과 같은 리팩토링 설명의 중복
4. 작은 기능의 클래스 트리·설정 목록
5. 본문과 그림에서 반복되던 호출 순서

## 남긴 핵심

- 데이터 기반 적·패턴 확장과 공통 GA 계약
- Spec·요청 ID, 잠금 소유권, 실행 제한·후딜·공통 공격 간격
- 소켓 Sweep, 대상별 중복 방지, 피해 전달과 실제 피해 수신의 구분
- 페이즈 상태·진입 ID, 보조·상시 패턴, 자원·위험도, 기믹 완료 검증
- 보스방 수명과 스테이지 Director의 책임 분리, 실패·재도전 정리
- 시네마틱 핸들·재진입 방어, 명시적 Cancel, 스킵 마커와 입력 복원
- 방 단위 컷어웨이·캐시·복구, 진행 플래그와 시간대 복원
- 실제 측정 수치와 에디터 실행 조건·해석 한계

## 실제 설정에서 확인할 항목

| 우선순위 | 확인 사항 | 본문 처리 |
|---|---|---|
| 높음 | 이전 조사 `Saved/ClaudeRefactorWork/s5_apply.json`에 시간대 컨트롤러 `sky: null` 기록이 있다. 현재 맵의 Sky 참조와 하늘 BP 인터페이스 구현을 확인해야 한다 | 하늘까지 적용 완료했다고 쓰지 않고 연결 조건을 명시 |
| 높음 | 현재 Stage3 LI·페이즈 데이터·시퀀스의 참조와 KeepState·제한 시간을 에디터에서 확인 | 고정 에셋 버전·모든 페이즈의 고정 초 수를 제거 |
| 높음 | SC_BGM의 부모 계층과 새 음원의 SoundClass를 확인 | 두 채널 독립성의 조건을 명시 |
| 중간 | 플래그 키, 자물쇠 개수, 큐 슬롯, NavMesh와 복귀 지점을 실제 맵에서 확인 | 일반 클래스 계약과 실제 배치 완료를 구분 |
| 중간 | 성능 측정 하드웨어·드라이버·품질 설정과 화면 밖 근접 보정의 비교군 포함 여부 확인 | 기존 측정과 현재 보정 구현을 구분하고 인과관계를 과장하지 않음 |
| 중간 | 패키지 빌드 동일 경로 재측정 | 에디터 -game 결과임을 유지 |

v7은 이미 코드 대조한 v6의 설명을 재편한 문서다. 이번 개편에서 게임 코드를 수정하거나 전체 플레이 테스트를 새로 수행하지 않았다. 구현 대조의 자세한 근거는 보존된 `기술문서_전선현_담당절_수정본_v6.check.md`에 남아 있다.

## 통합과 그림

- 고정된 담당 절 번호를 유지했다. 3.5·6.3·6.5.2·9.2 등 공동 절은 통합 시 각 담당자의 기본 원고와 병합해야 한다.
- 구조·흐름 그림 11개 중 패턴·피격·기믹·시네마틱의 4개는 호출 순서를 시퀀스 다이어그램으로 새로 표현했다.
- 빈 촬영 영역은 제거했다. 최종 통합 문서에는 패턴 설정, 근접 판정 디버그, Stage3 전환, 가림 전후, 조명 전후의 실제 캡처를 필요에 따라 추가하면 된다. 현재 28쪽은 이 캡처를 넣기 전 분량이다.
- 본문 변경은 기여의 수치 평가가 아니다. 문서의 설명 책임과 어필할 기술의 비중에 따라 분량을 배분했다.
